## 最终在线判据

会话必须初始化和启动成功，账号身份匹配，MSF 状态 `(1, 0)`，dispatcher 健康，没有未知依赖且未停止。在此基础上，还需以下任一证据：

1. driver 绑定同一账号、UID 与流程代次的明确原生登录成功；
2. 实际实时、非导入的原生在线消息。

明确成功兼容整数 `0` 与规范字符串 `"0"`。认证 getter 默认、异常或递归均不能产生成功；仍等待的原生快速登录 Promise 保持原样，不伪造登录结果或消息。最终冷启动在零入站时的实际就绪已证明第一条路径可用。

## 群列表与消息映射

群通知 `0/1` 替换完整快照、`2` 增量更新、`3` 删除、`4` 和未知类型保持缓存。缓存最多 10000 条公开 DTO，未取得完整快照前不声明全量；空 no-change 不清空已有群。

原生 19 位消息 ID 保持字符串。OneBot 正 int32 别名和去重状态为进程内 FIFO，默认容量 5000；淘汰和重启后失效。映射不保存正文或昵称，未知非文本内容不会伪装为文本以外的受支持消息。

## 覆盖界限

- 完整 Docker 新数据卷的扫码后账号会话和文本收发尚未再次验证。已经确认的登录、收发及最终冷启动来自同源原生实验宿主；容器新卷证据止于真实取码和生命周期。
- 最终 116 进程的只读动作、自然原生消息批次和群缓存验证，与整合运行阶段捕获的真实 OneBot 事件分别记录，不将不同阶段混为同一次测试。
- 仅发送过用户明确允许的那一次测试消息；本记录不声明重复发送、自动补发、长期送达或跨进程幂等验证。
- 只支持当前已验证的 QQ 构建和 x64。其他 QQ 版本、ARM64、长期稳定性、完整 @、图片文件、私聊与多账号未纳入本次完成范围。
- 源码采用 MIT，已公开发布于本项目 GitHub 仓库；尚未实现全部接口能力，也没有提供腾讯商业运营授权或法律保证。

官方 QQ 准备脚本已完整下载和解压成功，本地摘要记录见 [PROVENANCE](PROVENANCE.md)。依赖审计 `npm audit --omit=dev --audit-level=high` 返回 0 个已知漏洞；这不替代整体安全审查。
