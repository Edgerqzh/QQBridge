# 引用、消息查询、历史和群成员

版本 `0.4.0-dev.1`。原生运行仍限定官方 Linux QQ `3.2.34-53644` x64。以下接口均要求当前账号真实在线，目标群在当前成员关系和白名单内。查询不向群发送消息。

## 接口

| 动作 | 参数 | 返回 |
| --- | --- | --- |
| `get_msg` | `message_id`，桥接层正 int32 ID，也接受规范十进制字符串 | 消息时间、发送者、消息段、群号及原生 ID / 序号扩展 |
| `get_group_msg_history` | `group_id`、`count`（默认 20，范围 1–100）、可选 `message_id` | `messages`、`next_message_id`、`unsupported_count` |
| `get_group_member_list` | `group_id`、可选布尔 `no_cache` | 当前完整成员数组 |
| `get_group_member_info` | `group_id`、`user_id`、可选布尔 `no_cache` | 单个成员；不在群内返回 `1404` |

上述 HTTP 和 WebSocket 动作使用现有 Bearer 鉴权。历史查询是扩展接口，不属于 OneBot 11 标准公开 API。示例以虚构群号和消息 ID 表示；请替换为实际事件或历史返回值。

```json
{"action":"get_group_msg_history","params":{"group_id":10001,"count":20}}
```

不带游标时读取 QQ 本地消息数据库中最近的记录。返回按群序号从旧到新排列；使用 `next_message_id` 再请求，可读取该条之前的记录，排除游标自身。不支持 `message_seq` 参数，避免把原生序号和桥接消息 ID 混用。不承诺获取服务器上所有漫游历史。

不支持的消息元素不会伪装成文字，历史中的这些记录计入 `unsupported_count`，游标仍前移；因此 `messages: []` 不一定表示历史结束，需同时检查 `next_message_id`。查询不会重新推送历史为实时消息，也不会改变已查询记录的实时去重状态。

`get_msg` 的 `message_id` / `real_id` 均使用桥接别名；`native_message_id` 是精确保留的原生十进制字符串，`message_seq` 是群序号字符串或 `null`。不应把原生 ID 转成 JavaScript Number。无法表示的消息返回 `1404`；已撤回或数据库已清理的记录可能不再可查。

## 引用回复

启用 `QQBRIDGE_EXPERIMENTAL_RICH_MEDIA=1`，发送时把唯一 `reply` 段放在首位，并附带实际内容：

```json
{
  "action":"send_group_msg",
  "params":{
    "group_id":10001,
    "message":[
      {"type":"reply","data":{"id":"123"}},
      {"type":"text","data":{"text":"收到这条消息了。"}}
    ]
  }
}
```

引用目标必须属于同一群，且能通过真实原生记录查回；发送前读取其原生 ID、群序号、发送者和时间，不接受调用者伪造这些字段。引用过期、跨群或查询失败时不尝试发送，也不自动重发。

接收引用时，部分手机消息的 `replayMsgId` 为 `0`。驱动使用真实群序号查询来源，再登记到同一套 ID 映射；不会将 `sourceMsgIdInRecords` 直接当作可用的本地原生 ID。来源在 QQ 数据库中不可用时保留可显示正文，省略无法解析的引用，并在 `get_login_state.context_reads.unresolved_replies` 中累计。引用来源补查共用最多两秒预算。

## 群成员

每次调用都主动刷新原生完整列表；相同的并发读取合并为一次请求。即使 `no_cache=false` 也使用新读取，不自行维护成员资料缓存。原生缓存存在 `finish=true` 但缺失成员的实测情况；刷新仍不完整时明确失败，不返回声称完整的部分列表。单次最多 10000 个成员。

返回真实可用的昵称、群名片、入群时间、最近发言时间、等级、角色、专属头衔和禁言时间。当前角色映射为原生 `2/3/4` → `member/admin/owner`。性别、年龄和地区在此原生记录中不可用，返回 `unknown`、`0`、空串，不代表用户实际资料；不声明不确定的名片修改权限等字段。成员资料不写入桥接层索引。

## ID 持久化与限制

映射保存在私有 profile 的 `message-index/<账号>.json`，含桥接 ID、原生消息标识、群信息、去重标记和分配高水位，不含正文、昵称或媒体内容。目录权限为 0700，Linux 文件权限为 0600。写入使用临时文件、文件同步、原子替换和目录同步。

发送成功回执、查询结果和实时事件对外返回前，相关 ID 先写入磁盘。同账号、同 profile 重启后 ID 保持；发送过的 ID 可继续用于查询、引用及权限允许的撤回。索引仍是最近 5000 条 FIFO 窗口，淘汰后返回未知或过期；分配高水位不回退、不复用淘汰 ID，正 int32 空间耗尽时失败。

索引损坏或账号不匹配时拒绝初始化，不静默清空后从 1 重新分配。磁盘写入失败时不发布未持久化的新 ID；若 QQ 已受理发送，则错误明确要求不要重发。此机制不是持久化事件队列，不承诺崩溃期间事件零丢失或恰好一次投递。一个 profile 仅供一个 runtime 使用。

升级前旧版仅存内存的 ID 无法凭磁盘恢复；本版本持久化保证从新索引建立后开始。保留原有 profile 和账号资料卷，不要将索引提交到公开仓库。

原生上下文读取最多四个并发，相同请求合并；默认八秒超时。已超时但尚未结束的原生 Promise 保留并发名额，过载返回 `1429`。账号、会话和群权限在读取前后都检查。实时事件等待队列最多 2500 条，溢出会令 `good=false`，不会无限积压。文件下载与音频转码继续使用各自独立限额。
