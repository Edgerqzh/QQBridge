# QQ 资料与空间凭证动作

本分支从 `5153c45`（v0.10.0）开始开发，尚未合并或发布。
基线的资料修改、`get_cookies`、`get_credentials` 没有实现；
`get_stranger_info` 使用好友查询路径，机器人自己不在好友目录时也返回 1403。

## 独立开关

两组能力默认关闭，只在运行原生驱动的进程中设置 `1` 才启用：

```dotenv
QQBRIDGE_ENABLE_PROFILE_ACTIONS=1
QQBRIDGE_ENABLE_QZONE_CREDENTIALS=1
```

Linux 原生 Compose 与加密资料 Compose 均传入这两个变量，默认值是 `0`。
Windows 使用自己的私有环境文件。两个开关互不依赖，也不依赖媒体消息开关。
关闭时新动作返回 1404；资料开关也控制 `get_stranger_info` 新增的查自己分支。
查询其他人的好友资格、私聊白名单等限制保持原样，`get_friend_info` 不增加自查分支。

## QQ 资料

成功响应为 `status: "ok", retcode: 0`。下表描述其 `data`。

| 动作 | 参数 | 成功 data |
| --- | --- | --- |
| `get_stranger_info` | 自己的 `user_id`；可选布尔 `no_cache` | `{user_id, nickname, nick}` |
| `set_qq_profile` | 可选 `nickname`、`personal_note`，至少一个 | `{}` |
| `set_self_longnick` | `longNick`，兼容 `long_nick`、`longnick` | `{}` |
| `set_qq_avatar` | `file`，仅规范的 `base64://` 编码 | `{}` |
| `set_online_status` | 整数 `status`、`ext_status`、`battery_status`，均必填 | `{}` |

昵称为 1～36 个 Unicode 字符，签名为 0～255 个 Unicode 字符，拒绝非法代理项和控制字符。
`personal_note` 可以单独提供；未提供的字段不进入原生修改方法。
签名允许空字符串，以清空原签名。多个签名别名同时出现时必须是相同字符串，否则返回 1400。
修改多个字段前先检查所需方法；若前一个字段已修改、后一个字段未成功，返回 1500，避免把部分成功误认为全未执行。

头像限制为 1 字节～4 MiB 的 PNG 或 JPEG，宽高各 1～4096 像素，总像素不超过 16,777,216。
拒绝 URL、本地路径、非规范 Base64、截断数据及其他图片类型。检查文件结构后，在独立图像进程中完整解码；多页图片不接受。
原生上传只收到私有资料目录中临时图片的路径。即使调用方已经超时，也等待原生请求结束后再删除其输入文件。
该临时文件不是空间凭证缓存。

基础状态只接受以下组合，电量为 0～100 的整数：

| 状态 | status | ext_status |
| --- | --- | --- |
| 在线 | 10 | 0 |
| 离开 | 30 | 0 |
| 隐身 | 40 | 0 |
| 忙碌 | 50 | 0 |
| 请勿打扰 | 70 | 0 |

自定义状态要求 `status=10`，`ext_status` 使用以下已知编号；例如听歌中为 1028，今日天气为 1030。
未列出的编号或与其他基础状态组合均返回 1400。

```text
1000,1011,1016,1018,1021,1027,1028,1030,1032,1051,1052,1056,1058,
1059,1060,1061,1062,1063,1070,1071,1201,1300,1401,2001,2003,2006,
2012,2013,2014,2015,2019,2023,2025,2026,2037,2050,2053
```

资料读取只向原生服务请求当前账号 UID；`no_cache=true` 先从服务器刷新，再提取昵称。
修改昵称和签名分别使用原生资料服务的专用方法，头像使用 `setHeader`，状态使用消息服务的 `setStatus`。
不自行添加修改频率窗口，不合并修改请求，不自动重试。

## 空间凭证

| 动作 | 参数 | 成功 data |
| --- | --- | --- |
| `get_cookies` | 必填 `domain` | `{cookies}` |
| `get_credentials` | 必填 `domain` | `{cookies, csrf_token}` |

`get_csrf_token` 未增加实现。QQBridge 不发布动态、不上传空间图片、不提供视频扩展动作。

域名先转成小写、去掉一个 `https://` 前缀及一个末尾 `/`，之后只允许：

```text
user.qzone.qq.com
qzone.qq.com
h5.qzone.qq.com
mobile.qzone.qq.com
```

端口、路径、用户信息、通配符、查询参数、片段或空白等格式错误返回 1400。
缺少 `domain`，或格式正确但不在白名单的域名，返回 1403。
拒绝 `qq.com`、`qun.qq.com` 等域名，不将调用方的任意域名传给原生服务。
四种允许的写法始终只调用 `getTipOffService().getPskey(['qzone.qq.com'], false)`。

Cookie 字符串恰好包含四个名称：

```text
uin=o<账号>; p_uin=o<账号>; skey=<标准票据或空>; p_skey=<空间域名票据>
```

`p_skey` 必须来自结果中精确的 `qzone.qq.com` 键，缺失或格式异常即失败。
当前实测 SDK 只返回域名票据，没有单独提供 `skey`；此时 `skey=` 保留为空。
若该原生返回对象确实提供独立 `skey`，则经相同的 Cookie 值校验后返回。
绝不使用 A2、客户端密钥或通用登录数据填补 `skey`，也不把其他域名票据充作空间票据。
这意味着调用方若硬性要求非空标准 `skey`，需要自行识别这一能力限制。
`csrf_token` 是对实际空间 `p_skey` 计算的 DJB 哈希，并取低 31 位。

QQBridge 不记录凭证、不写入自己的文件或日志，也不缓存接口返回值；仅将过滤后的结果返回给已鉴权请求。
原始 SDK 响应、额外字段和异常诊断不进入响应。凭证读完后不会自动调用任何空间网页写入接口。

## 错误与超时

| retcode | 含义 |
| --- | --- |
| 1400 | 参数、域名格式、编码、图片或状态组合错误 |
| 1403 | 域名或对象不允许、账号不可用，或明确的原生次数／策略限制 |
| 1404 | 开关关闭，或当前原生版本缺少对应方法 |
| 1504 | 准备阶段超时或取消，可确定没有发出修改 |
| 1500 | 已发出修改但结果未确认、部分资料已修改，或无法确认原生结果 |

错误使用简短中文描述。原生拒绝时可以附带数值错误码，不返回原始错误正文、凭证或文件路径。
原生修改、内部 IPC 或网关等待超时均不重试；请求已发出时返回 1500。
准备阶段异步工作即使稍后完成，也会检查截止时间和账号会话，不能继续发出过期修改。
HTTP 状态码沿用网关映射，调用方仍需读取 OneBot JSON 中的 `retcode`，不能仅凭 HTTP 异常判断操作是否执行。

## 验证记录

- 完整 Windows 回归共 277 项：275 通过、2 项因缺少 FFmpeg / ffprobe 跳过，0 失败。
- 新增单元及集成测试覆盖两组独立开关、自查与好友隔离、参数与别名、已知状态组合、域名规范化与拒绝、精确四个 Cookie、无通用登录回退、CSRF、头像完整解码、敏感错误过滤和修改超时不重试。
- 真机自查：启用开关后，当前账号及 `no_cache=true` 查询成功，无需好友目录放行自己。
- 真机凭证：两种动作均成功，返回精确四个名称和有效空间票据；标准 `skey` 为空，`get_credentials` 返回整数 CSRF。测试输出仅保存布尔结果，不保存票据。
- 真机签名：`set_self_longnick` 返回成功，使用者确认显示正确。
- `set_qq_profile` 单独传 `personal_note` 的逻辑已通过单元与驱动集成测试；真机仅尝试一次，没有取得可确认的成功结果，界面仍是前一次签名，不重试、不计为通过。
- 真机昵称与头像各尝试一次，原生返回成功；使用者确认昵称与蓝色测试头像显示正确。重新查询昵称与预期一致。
- 真机忙碌状态修改成功，使用者确认显示正确；之后按授权恢复在线，原生返回成功。
- 使用独立工作目录、资料目录、端口和令牌；原有稳定性监测进程及其配置未修改。使用者确认沿用原测试账号后才进行这些真机操作。

以上不是所有客户端版本、平台或审核情形的兼容性结论。两个原生加载器均接入了默认关闭的开关；本轮真机使用固定版本的 Windows 原生客户端，Linux 的新动作未做真机验证。
