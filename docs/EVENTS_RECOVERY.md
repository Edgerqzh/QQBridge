# 撤回、成员事件与掉线恢复

版本 `0.5.0-dev.1`，2026-10-30。原生能力仍限定官方 Linux QQ `3.2.34-53644` x64。事件使用现有带鉴权的正向 / 反向 WebSocket 连接；不要求启用富媒体实验开关。

## 通知事件

| `notice_type` | 字段 | 行为 |
| --- | --- | --- |
| `group_recall` | `group_id`、`user_id`、`operator_id`、`message_id` | 原消息撤回通知；发送者和操作者分别解析 |
| `group_increase` | `group_id`、`user_id`、`operator_id`、`sub_type` | 结构化入群记录；子类型为 `approve` 或 `invite` |
| `group_decrease` | `group_id`、`user_id`、`operator_id`、`sub_type` | 成员减少；子类型为 `leave`、`kick` 或 `kick_me` |

事件另含 `post_type: "notice"`、`self_id` 和秒级 `time`。标准字段参照 [OneBot 11 通知定义](https://github.com/botuniverse/onebot-11/blob/master/event/notice.md)。

撤回来自原生 `onMsgInfoListUpdate` 或新消息中的结构化灰条。原生 `onMsgRecall` 的结果回调不是群撤回事件依据。原消息更新后的 ID 保持不变，沿用现有桥接别名；新遇到的撤回记录也登记到同一套持久化映射。原发送者和实际操作者使用原生 UID → QQ 号映射，无法确认时不猜测。撤回记录的 `isOnlineMsg` 可以为 `false`，不能因此忽略原生更新通知。

成员事件读取结构化 `groupElement`，不解析中文提示文本，不猜测未验证的枚举值。加入依据明确的申请 / 邀请结构；未知加入操作者返回 `0`。减少事件要求该成员存在于之前的完整快照中，并经当前完整列表确认已经离开，再区分主动退出与管理员移除。当前 QQ 自身被移出时，还可使用已确认的群列表移除证明失去成员关系，避免继续查询无权访问的群。

成员快照仅保存在内存，最多跟踪白名单允许的 256 个群，每群最多 10000 人。首次快照只建立基线，不上报全员入群；缓存刷新、群名或角色变化、未完成的列表不作为进退群事件。快照未建立、快速进出发生在两次完整读取之间、字段不完整或原生读取失败时，可能无法确认对应通知，计入诊断指标。恢复连接后重新建立基线，不补造断线期间的进退群记录。

通知去重键按账号保存到消息索引，最多 5000 条，与消息 ID 一起原子持久化后再推送。重复的原生更新和同 profile 重启不会在该窗口内再次上报。通知队列与消息共用 2500 条上限，原生资料查询最多四个并发、单次三秒；已超时但未结束的原生 Promise 保留名额。

## 连接恢复

完整原生容器提供自动恢复：

1. 已初始化的会话掉线后，等待 15 秒，让 QQ 原生网络栈自行重连。期间对外报告离线，发送接口拒绝新发送。
2. 短暂网络中断恢复后，保留原会话和 ID；群权限缓存失效，等待新群列表后恢复群操作。
3. 持续掉线、已失效的登录传输或内部 IPC 断开时，正常停止并重新启动原生 worker。网关保持运行；不在同一进程重复初始化旧 QQ kernel。
4. supervisor 对原生进程退出使用 1、2、4、8、16、30 秒退避，每十分钟最多六次自动重启。超限转为新二维码登录；如果该备用 worker 本身仍失败，保留网关离线状态并停止重启，等待修复配置后重启服务。
5. QQ 踢下线 / SSO 认证错误要求重新扫码，自动恢复不代替用户确认。没有允许保存登录的账号同样转为扫码，不擅自选择缓存列表中的其他账号。

原生 worker 使用退出码 `75` 请求自动重建，`76` 请求强制二维码模式。手动启动 runtime 的部署方式需要外部进程管理器处理退出；本项目的容器 supervisor 已内置这些规则。

恢复不重放应用的发送动作。发送已被 QQ 受理后遇到断线或持久化错误，仍保留“不要自动重发”的错误语义。消息映射和通知去重继续保存在原 profile；这不是持久化事件队列，不保证断线期间零丢失或恰好一次投递。

## 状态与验证

`get_login_state` 增加：

- `recovery.phase`：`idle`、`online`、`waiting`、`restart_requested`、`manual_required`。
- `recovery.reason`、`last_online_at` 和 `restart_requested`：最近恢复状态。
- `recovery.manual_reason`：新二维码模式的进入原因。
- `notices`：通知计数、无法解析数、原生查询并发、跟踪群数量等。

登录网页会显示恢复中或需要重新扫码，并清除过时的“已在线”显示。

本轮完整回归：Linux 192/192 通过；Windows 191 通过、1 项因宿主缺少 FFmpeg 跳过。新增验证包含重复撤回、ID 复用、持久化通知去重、邀请 / 申请结构、主动退出 / 踢人 / 当前 QQ 被移出、快照缺失、未知成员、权限失效、读取超时、短暂掉线、持续掉线、认证失效和重启预算。IPC 关闭使用有期限的 WebSocket 关闭握手，避免旧连接尚未释放时立即替换。

真实 QQ 验证：

- 用户发送后撤回测试消息，带鉴权 WebSocket 收到一次 `group_recall`，ID 与已收到的原消息一致。重复的原生更新未再次上报。
- 强制中断原生进程后，网关进程保持，原生 worker 自动重启，账号恢复在线，旧消息 ID 查询成功。
- 将测试容器网络隔离 45 秒再恢复，确认掉线、重新在线、未要求重新扫码、旧 ID 仍可查；修正了普通错误码退出引发整个容器重启的问题。

真实成员进退群尚无备用测试账号，当前仅完成结构字段检查和自动化验证，不宣称已经群内实测。以上仍是指定构建和一个测试群的短期验证，不替代连续多天、多群和高负载测试。
