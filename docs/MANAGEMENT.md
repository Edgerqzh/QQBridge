# 好友申请与群管理（0.7 开发预览）

面向官方 Linux QQ `3.2.34-53644` x64。所有接口使用现有 HTTP / WebSocket 鉴权。好友申请不会自动同意；群管理操作由调用方明确发起，原生请求失败或超时后不会自动重试。

## 好友申请

| 接口 | 参数 | 行为 |
| --- | --- | --- |
| `get_friend_requests` | 无 | 获取最近 7 天尚未处理的普通入站好友申请 |
| `set_friend_add_request` | `flag`、`approve=true`、`reason=""` | 同意 / 拒绝指定申请；`reason` 为拒绝理由，最长 120 字 |
| `add_friend` | `user_id`、`comment=""`、`remark=""` | 扩展接口：向指定 QQ 发出一次好友申请；验证信息最长 120 字，备注最长 60 字 |

收到申请时上报 OneBot `post_type: "request"`、`request_type: "friend"`，包含 `user_id`、`comment`、`time`、`self_id` 和不透明 `flag`。将 `flag` 原样传回处理接口，不能从 QQ 号自行拼接。一个进程内相同申请通知去重；重连或重启可能重新上报仍待处理的申请，接入端也应按 `flag` 去重。

```json
{
  "action": "set_friend_add_request",
  "params": {"flag": "从申请事件或列表复制", "approve": true}
}
```

申请读取同时等待原生 ACK 与完整回调，再将原生 UID 解析为 QQ 号。`QQBRIDGE_ALLOWED_USERS` 同时限制申请上报、处理和主动添加。空配置允许所有目标；已有好友私聊范围不变。

主动添加会先确认目标尚非好友，再核对 QQ 返回的账号、原生 UID 和加好友策略。仅支持不含问题的普通策略（当前 SDK 的 0 / 1）；问答、验证码、安全验证、手机号查找和其他策略返回不支持，不能绕过。`request_sent: true` 表示原生接口受理，最终是否成为好友仍取决于 QQ 和对方确认。

处理入站申请前，把决定的摘要写入专用 profile 内的 `management-claims.json`，避免重复处理。该文件按账号与申请隔离，最多保留 2048 条、7 天记录，不包含申请正文或原生 UID 明文。失败 / 结果未知的尝试也会保留；接口返回 `1409` 时先在 QQ 中确认结果。损坏的记录文件会阻止处理申请，不能直接忽略错误继续执行。请随账号资料一起备份，勿提交至公开仓库。

审批接口的非空 `remark` 暂不支持，会在执行前返回 `1404`，不会悄悄忽略。主动添加的备注通过原生申请参数传入。

## 群管理

| 接口 | 参数 | 权限及边界 |
| --- | --- | --- |
| `get_group_info` | `group_id`、`no_cache=false` | 已加入且在允许范围的群；群名来自原生群快照，人数来自本次完整成员列表 |
| `set_group_ban` | `group_id`、`user_id`、`duration=1800` | 管理员 / 群主；0 为解除禁言，最大 2592000 秒 |
| `set_group_whole_ban` | `group_id`、`enable=true` | 管理员 / 群主；false 为解除全员禁言 |
| `set_group_kick` | `group_id`、`user_id`、`reject_add_request=false` | 管理员 / 群主；一次只处理一个成员 |
| `set_group_admin` | `group_id`、`user_id`、`enable=true` | 仅群主；true 设为管理员，false 取消 |
| `set_group_card` | `group_id`、`user_id`、`card=""` | 可改自己名片；修改他人需要相应管理权限；最长 60 字 |
| `set_group_name` | `group_id`、`group_name` | 管理员 / 群主；非空，最长 60 字 |
| `set_group_leave` | `group_id`、`is_dismiss=false` | 普通成员 / 管理员退群；群主需先转让，不支持解散群 |

`enable`、`approve`、`reject_add_request`、`is_dismiss` 必须是 JSON 布尔值，不能传字符串。QQ 号 / 群号接受安全整数或十进制字符串。

所有群写操作都先验证 `QQBRIDGE_ALLOWED_GROUPS`、已观测的群成员身份，再向服务器刷新完整成员列表。核对当前账号 UIN / UID 和角色后才调用修改方法。普通成员不能管理他人，管理员不能操作同级管理员 / 群主，不能禁言或踢出自己。原生 QQ 仍会执行最终权限与策略检查。

同一个群只允许一个在途管理操作，整个管理模块最多四个并发。默认 8 秒超时；未完成的原生操作继续占用名额，不能因为 HTTP 超时而无限发起新请求。读取超时后不会继续迟到的写操作；已调用写接口后超时会明确返回结果未知，调用方必须先查询 QQ 状态再决定下一步。

当前不含匿名管理、专属头衔、群申请审批、群公告、批量踢人、转让或解散群。群管理成功 ACK 不会被伪装成成员变动或管理通知。

## 验证记录

自动化回归共 229 项：Linux 229 项通过；Windows 228 项通过，1 项因宿主缺少 FFmpeg 跳过。新增 23 项覆盖管理权限与 UID 定位、成员 / 群允许范围、完整快照校验、所有已实现写操作的原生参数、失败 ACK、超时不重复执行、好友申请事件与过滤、持久化审批去重、损坏记录和主动添加策略校验。

真实账号已验证好友申请完整回调、UID → QQ 号解析和待处理列表。经用户明确允许，仅同意一条新申请，刷新好友列表后确认该用户已成为好友；未处理旧申请。测试 QQ 的群名片也完成“改为测试值 → 服务端查询匹配 → 恢复原值 → 再次查询匹配”，未发送聊天消息。

最终源码重启后，新好友、原群名片及旧私聊消息 ID 均保留，已同意的申请不再出现在待处理列表。带鉴权的 OneBot WebSocket 捕获真实 `request/friend` 事件，包含有效 QQ 号、字符串验证信息和不透明 flag；测试记录只保存判断结果。

当前测试 QQ 在群内为普通成员。禁言、踢人、管理员、群名、退群等操作的参数与权限检查通过自动化测试，尚未执行真实群修改；主动发起好友申请也尚未完成真实发送验证。接口受理不等同于用户可见效果，当前仍是开发预览。
