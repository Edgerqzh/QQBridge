# 本地扫码登录网页

在与网关使用同一个 `.env` 的源码目录执行：

```bash
npm ci
npm run login:web
```

打开 [http://127.0.0.1:5702/](http://127.0.0.1:5702/)。网关和原生运行时需要先启动，例如 `docker compose --env-file .env -f compose.native.yaml up --build -d`。

页面显示动态二维码、有效期、手机确认及在线状态；二维码失效或服务断开时隐藏旧码。点击“获取新二维码”会中止旧的原生二维码会话后重新获取，首次取码不取消尚不存在的会话。根路径、`/login`、`/login/` 均可访问。

“记住这台电脑的登录”会设置原生保存登录偏好，并只保存这次由用户确认选中的账号。下次启动可恢复这个明确选中的账号，不自动选择缓存列表中的首个账号。`QQBRIDGE_LOGIN_UIN` 的显式配置优先；`QQBRIDGE_FORCE_QR=1` 可跳过保存的选择，强制重新扫码。客户端登录许可失效时仍需要手机重新确认。

登录网页仅绑定本机回环地址。主 API 令牌只保留在本地服务端，不进入 HTML、前端脚本或浏览器存储。网页代理仅允许登录状态和二维码操作；不提供消息发送入口。来源与 Host 校验拒绝跨站请求，页面禁止被其他站点嵌入。

手动部署可设置 `QQBRIDGE_UI_PORT`（默认 5702）和 `QQBRIDGE_UI_API`（默认 `http://127.0.0.1:5700`，仅允许本机 HTTP 地址）。网页服务与 QQ 网关可以分别重启，账号和媒体资料保存在原生 profile 中，不进入源码发布包。

多机器人产品部署应为每个机器人分配独立加密资料卷和端口，参见 [加密账号存储](ENCRYPTED_STORAGE.md)。保存的账号选择不等于完整登录票据；恢复需要完整 profile、原设备标识及原生客户端许可。
